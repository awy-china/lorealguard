## D-07 子进程编码：**两侧没说好**的一类 bug（2026-09-22 新增，当天在三个地方各中一次）

- **性质**：Windows 本机 locale = GBK。父进程 `subprocess.run(..., text=True)` **不给 `encoding=`**
  就按 locale 解码；而子进程未必按 locale 吐字（可能被环境变量、或它自己钉成 UTF-8）。
  两侧不一致时，`subprocess` 的 `_readerthread` 抛 `UnicodeDecodeError`，**`proc.stdout` 变成空串**。
- **当天实测的三处 + 两天后补齐的同族两处**（全部已修，守卫见
  `tests/test_encoding_guard_falsifiability.py` 的 M44–M50）：
  1. `tools/check_number_consistency.py` —— 输出带 `✅`/`❌`，stdout **一重定向到文件**就自己崩、**exit 1**。
     后果最重：CLAUDE.md §5 明令别用 `| tail`（会吃退出码）、推荐的正是重定向到文件 ——
     于是"唯一推荐的跑法"恰恰是这条崩溃路径，看的人会以为**数字漂移了**，去改本来没错的数字。
     修法：`_utf8_stdout()`（`stream.reconfigure(encoding="utf-8", errors="replace")`）。
  2. `tests/test_rebuild_from_scratch.py` —— 子进程 env 里写了 `PYTHONIOENCODING=utf-8`，
     父进程却按 locale 解。修法：父进程补 `encoding="utf-8", errors="replace"`。
  3. `tests/test_cli.py` —— 只在**外部环境带** `PYTHONIOENCODING` 时才崩 ⇒ **成败取决于环境变量**。
     修法：子进程 env 里钉 `PYTHONIOENCODING=utf-8` **并且**父进程补 `encoding=`（两侧都钉死，与外部无关）。
- **代价（要说清，别夸大）**：这三处**都不是假通过** —— 它们的闸门是 `returncode`，不靠 stdout。
  真实代价是**失败时诊断信息全空**（跑红了只看到「失败：」后面什么都没有），
  外加每次跑留 4 条 `PytestUnhandledThreadExceptionWarning` 噪音。**"看不见为什么红"正是修不动的原因。**
- **同族残留（2026-09-22 已补齐，本段是当日"只登记未动"的更正版）**：
  1. `tools/record_all_demo.py` 的 `grab_frame`（A/B/C 抽帧）与 `tools/record_demo_page.py` 的
     `grab_frame`（产品四镜抽帧）—— 抽帧时 `text=True` 无 `encoding`，**已补**
     `encoding="utf-8", errors="replace"`，守卫 M49/M50。
     ⚠️ 原登记说「ffmpeg 的 `-loglevel error` 输出是 ASCII，今天没崩」—— **实测是错的**：
     ffmpeg 把打不开的路径**原样回显**（UTF-8 字节），抽帧路径含非 ASCII 时读线程崩、
     `r.stderr` 变成 **`None`**（不是空串）→ `f"抽帧失败：{r.stderr.strip()[:200]}"` 抛
     `AttributeError: 'NoneType' object has no attribute 'strip'`（实测于 `tools/record_all_demo.py:86`
     与 `tools/record_demo_page.py:277`）。**录屏工具在最该说清"为什么抽不到帧"时崩成另一种错。**

     而 `probe()` 只读 stdout（`-of default=nw=1` 吐的全是数字）⇒ 钉不钉都返回 `{}`，
     **行为上惰性**。留着只为消掉读线程崩溃的噪音警告。见变异体清单下方那段注释。
  3. 二进制模式、确实不受影响：`tools/record_demo.py` 的 `frame_std`（抽帧只判灰度 std，

## D-08 剪辑工具的两处盲区（2026-09-22 新增，**主动登记**）

`tools/make_film_segment.py` 负责把冻结素材剪成成片的产品两段（镜 4 / 镜 8）。它的自证有四条判据，
但下面两处**它证明不了**，必须自己说出来，否则"已自证"就成了包装。

- **① 「掐晚一帧」在硬切素材上原理上不可判**。判据 ④ 拿出片首帧与源片 onset ±1 三帧比 SSIM，
  要求 onset 那帧是（并列）最高。硬切之后 onset 与 onset+1 **逐像素相同** ⇒ 无论起点滑到哪一帧，
  相似度都一样。能判的只有「掐早」。
  **兜底**：帧数守恒（段长必须等于槽位，掐晚就少一帧、由卡片补齐）+ ③ 尾帧逐字读回。
  **这一层确实兜不住**，所以写在这里而不是含糊过去。素材是录屏，onset 处画面有实质变化
  （实测 D3/D4 前一帧互差 0.28/0.26）⇒ "掐早"一定抓得住；"掐晚一帧"需要人眼复核一次。
- **② 剪点依赖 `select` 表达式，工具不校验表达式本身的语义**。`clip_sel()` 生成

## D-11 「被引用的 token 可能根本不存在」+ 包内抬头是冻结产物（2026-09-24 新增，四件事同一轮实测）

D-10 说的是**数字**对不上文件；D-11 说的是另外两件更隐蔽的：**被引用的名字根本不存在**，
以及**改一句散文会换掉整个提交包的哈希**。

- **① `RUNBAT_EXIT` 是幽灵 token：交付报告引用它，全仓库没有任何东西打印它。**
  `loreal-redteam-report.md` 抬头第 17 行原文（现由 `tools/make_redteam_delivery.py:49` 固化）
  在写「`run.bat` 的一键验收里这是**第 7 步**（8 步全绿，`RUNBAT_EXIT=0`）」——
  而当时全仓库 grep 不到 `RUNBAT_EXIT` 这个字符串。**读者拿这句话去证据里找，是找不到的。**
  另一半更重：`run.bat` 末尾原本是 `pause` 且全脚本无 `exit /b`，cmd.exe 的 `%ERRORLEVEL%`
  取**最后一条命令**的返回码 ⇒ 恒 0。**所以那句"8 步全绿"无论 8 步炸成什么样都成立。**
  实测：让第 1 步 `sys.exit(7)`、末尾仍是 `pause`，调用侧拿到的还是 0。
  修法（2026-09-24 已做）：每步 `if errorlevel 1 if "%RC%"=="0" set "RC=n"` 累积，
  末尾 `echo RUNBAT_EXIT=%RC%` + `pause` + `exit /b %RC%`（`pause` 必须在 `exit` **之前**）。
  注意 `echo` 会把 ERRORLEVEL 重置为 0，所以第 7 步的重跑必须走 `goto :label` 绕开。

  **连带要重出印章 / PPT / PDF 并重录演示素材**（印章第三栏把 sha256 印进了图里）。
  已按输出区 zip 里那份老报告**逐字节还原**（1069 字节 / 20 行，恢复依据留在
  `output/_old_header.txt`）。⇒ **要补充说明写 `docs/DEBT.md`，不要写进这个抬头。**

  ①失败时 `exit /b` 把 7 传出去 ②日志里出现 `RUNBAT_EXIT=7` ③全绿时出现 `RUNBAT_EXIT=0`。

## D-25 — 判据窗口压在闸门边缘 ⇒ 这条判据**永远不可能绿**（2026-09-26 Hermes 实测）
- 现象：E2（成片）判据「镜 5–7 窗口 BGM 数字静音」实测 `max_volume -18.5 dB`，阈值 `≤ -80` ⇒ 红。而同一份 `_bgm.wav` 按每 10s 扫描，**80–120 四段全是 -91.0 dB**（本 build 的数字静音底），即归零**完全生效**。

## D-52 成片 BGM 用**无种子**粉噪 ⇒ 成片不可重放（2026-10-05，**已修**）

  口径不变（仍 −28 LUFS 的 60–400 Hz 底噪，`lufs()` 照量）。
