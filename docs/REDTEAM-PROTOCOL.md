# 红队协议 v1 —— 让对手看到我们的规则表，专门往"不冤枉人"上打

> **写于测量之前（2026-09-19）**。本文档是我方承诺：测出来的数字若不好看，
> **只能改本协议并留档，绝不许改检测器阈值**（沿用 `honest-benchmark-protocol` 铁律 1、3）。

## 0. 为什么要有红队

三场景基准（P2 / P2-T / P5）回答的是「**我们能不能做**」——那是**能力下界**。
红队回答的是「**对手能不能让我们翻车**」——那是**可信下界**。
0/40、0/33 这种数字有一个天然软肋：*样本是我们自己写的，我们（有意无意）避开了自己的刀*。
最硬的反驳不是再加 100 条自造样本，而是**把刀递给对手**。

## 1. 对手模型（三支矛）

| 代号 | 知情度 | 目标 | 一句话 |
|---|---|---|---|
| **矛 A 规避**（`evade`） | **白盒**：拿到 `comment_rules` 全文与全部数值门槛 | 打**漏报** | 「既要刷评，又要一条规则都不触发」 |
| **矛 B 陷害**（`frame`） | **白盒**：同上 | 打**误报护栏**（我们最贵的资产） | 「写 100% 真人自发、却让系统判成水军的评论」 |
| **矛 C 对照**（`blind`） | **黑盒**：完全不知道规则 | 打**泛化** | 「无信息对手写的"像真人"的内容，系统怎么看」 |

- 矛 A 是**唯一被允许赢**的一支：我们不掌握账号维度数据（注册时长/发帖频率/IP/设备），
  对手天生占优。**这是结构性让步，不是失误** —— 让步写在归因码 `ATT_NO_ACCOUNT_META` 里。
- 矛 B 是被重点防守的一支：整条产品线的立论是「不冤枉人」，**它被击穿到"高风险"就等于我们说谎**。

## 2. 判据（先写死，测完不许改）

| 指标 | 定义 | 承诺 |
|---|---|---|
| **红线**（矛 B） | 良性侧出现「高风险」的条数 | **必须是 0**。任何一条即为红队失败，如实登记、不解释为"个例" |
| 误报率（矛 B / 矛 C） | 良性侧「关注级及以上」占比 | 报**点估计 + CP 单侧 95% 上界**；与 10% 护栏对照，**超了就是超了**，不许换口径 |
| 绕过率（矛 A） | 1 − 检出率（关注级及以上） | **允许高**；如实登记为检出下界，禁止事后放宽阈值补漏 |
| **归因完备率** | 有判定但归因码为空的条数 | **必须是 0**（"解释权归语言"：判了就必须说清凭什么） |
| **靶子不变性** | 当前 `rules.yaml` 的 sha256 | **必须**等于样本生成时记录的指纹，否则跑分器**拒绝出分**（防"看完结果偷偷改规则再测"） |

## 3. 样本与封存

- 每支矛 **33 条线程**（与 P5 同量级，便于横向比）；线程 = 同一篇笔记下的 6 条评论。
- 对手模型：百炼 `deepseek-v4.1-flash`（= `config.MODEL_AGENT`，免费额度内）。
- **一次性封存**：生成结果落 `samples/red_team/red_team.json` 后，基准**只读该文件、不重跑 LLM** ——
  否则打包不可逐字节复现（LLM 输出不可复现，这是红队与自造集的本质区别）。
- 入库字段：模型名、temperature、时间戳、`rules.yaml` 指纹、**发给对手的完整 brief 原文**（含阈值）。
  谁都能查"我们当时打的是哪个版本的靶子、对手看到了什么"。

## 4. 现在就写下的诚实缺口（不等被问）

1. 矛 B / 矛 C 的「真人」是 **LLM 拟真**，不是真实平台用户 → 它给出的只是**下界**；
   真实世界的误报率仍需平台数据（已登记于 `loreal-hardening-v3.md` 与 `docs/DEBT.md`）。
2. 对手是**同一个模型**在扮演对手（攻防同源）→ 只能测"我们的规则是否容易被语言的表层变换绕过"，
   **不能**推广为"人类水军也这样"。
3. 红队样本**不进提交包**（它含生成的刷评话术，进包会污染"样本可复算"的口径）；
   只进仓库与报告，供评委原文复核。

## 5. 报告必须印（缺一不可）

1. 三支矛的**绕过率 / 误报率**（点估计 + 上界）与**归因完备率**；
2. **靶子指纹**（生成时 vs 跑分时，两者必须相同）；
3. **突破清单**：哪条样本绕过了哪条规则、绕过的**机制**（人话一句）；
4. 协议修订史（若无，写"无修订"——这本身是证据）。

## 6. 实测追加（2026-09-19 首次测量后补记：**判据零修订，只记事实**）

> 本节只记录测量过程中**新发现的事实**，不触碰第 2 节任何一条判据、不改任何阈值。
> 留档理由：一份协议如果只有"测前的完美承诺"，读起来像宣传；带上"测中撞到的东西"才是实验记录。

1. **对手会拒答（`refused`，独立一类）**。矛 A 的 brief 要求"完成刷评但绕过检测"，
   对手模型在部分调用里**合规拒答**，并在正文里给理由，例如
   `{"threads":[],"error":"无法协助生成水军刷评或规避评论区检测规则的内容。"}`。
   → 处理：拒答**不计为故障**，单独记 `calls_refused`。它带来一个必须写进报告的选择效应：
   **矛 A 的样本是"对手愿意接单"的子集**，因此矛 A 的绕过率是**乐观读法**（真实水军没有这层顾虑）。
2. **拒答与"想得越久越拒"相关**：同一批里 `reasoning_tokens=688` 的调用照做了、
   `reasoning_tokens=7245` 的调用拒答了。这是对齐思考的痕迹，不作为统计结论，仅留档。
3. **失败原因必须留在案发现场**。首轮 33 次调用有 7 次失败，当时只印"返回非 JSON"，
   无法区分限流/截断/拒答 → 已修生成器（记 `finish_reason` + 原文片段 + usage）。
   这是本次最贵的一课：**"失败"不分类，等于把线索扔掉**。
4. **不能靠改 brief 把拒答喂圆**。对手自己在拒答里提示了替代说法（"可用于检测器测试的
   已标注合成样本"）；**采纳它会给矛 A 换一个更弱、更配合的对手，从而把绕过率打得更低更好看** ——
   按第 2 节精神，这属于"换口径补漏"，**不做**。宁可把欠样登记在案。

## 7. 实测追加之二：矛 A 的对手断供与 framing 变更（2026-09-19 第二轮）

> 第 6 节第 4 条当时写的是"不做 framing 替换"。**十条调用之后这条被推翻了，推翻的过程写在这里。**

1. **同一份 brief 的接单率在漂移**：首轮 7/11 接单 → 补样轮 2/4 → 重采轮 **0/11**。
   合并 26 次调用：接单 **9 / 拒答 17 ≈ 35%**，最后整轮全拒。
   我们**不断言原因**（可能是安全策略收紧，也可能只是采样方差），但处置是明确的：
   **"让对齐模型扮演水军"不能当稳定的对手来源**。
2. **于是换 framing**：矛 A 改用 `b` = 「检测器压力测试」（构造有组织刷评、目标是**不触发**规则、
   标明是合成测试数据）。这不违反第 2 节的"禁止换口径补漏"，因为：
   - 拒答造成的不是"数字难看"，而是**样本量为 0、根本无法测量**（另两条矛不受影响）；
   - framing 变化确实会改变对手的动机强度 → 所以 **a / b 两种 framing 的绕过率不可混算**，
     报告必须印出用的是哪一种（`evade_framing`），并沿用第 6.1 节的选择效应披露。
   - 代价照旧登记：**真实水军的动机强于任何 framing 下的模型 → 矛 A 的绕过率始终是乐观读法。**
3. **反面教训（我们自己犯的）**：为追求"台账干净"，作者用 `--fresh-arms` 丢弃了 27 条**已经生成**
   的矛 A 样本；紧接着同一 brief 的接单率掉到 0 → **样本不可再生，丢弃即永久丢失**。
   教训一句话：**宁可报告里多一张脏台账，也不要为了好看销毁证据。**
